# 镜头审核平台

内网可通过 `http://10.10.10.247/` 或 `https://10.10.10.247/` 访问。制作方准备逐帧对比图，平台负责领取、标注、返修复核和审核留档。全帧通过后，作业进入「已通过」。

## 审核流程

1. 管理员上传送审 ZIP。相同管理员、作业名称和 ZIP 字节重复提交时打开已有作业。需要独立作业时，勾选「将相同文件作为独立新作业导入」。
2. 标注员领取，逐帧查看上下对比图。图片加载后可以通过或圈选问题。页面支持按状态筛选、放大、连续帧意见、同上张图和同一标签页的草稿恢复。
3. 「提交意见并退回」冻结本轮意见。管理员和原标注员可下载 JSON，或下载含编号圈选截图的 ZIP。
4. 管理员选择已退回的作业和基版上传返修稿。原标注员继续复审。仅在两版的原片摘要、对应帧起止时刻、画幅和图像相同的情况下，才沿用原人工通过。原片摘要来自送审清单。历史版本只读。
5. 已通过的作业可由原标注员开启补审。补审沿用同一套审核图，另存审核记录。退回后可提交更新后的图片。
6. 管理员可暂停、恢复和撤回作业。撤回的作业保留管理员审计记录并退出标注员列表。账号停用或密码重置立即撤销该账号的既有会话。作业的原标注员归属随历史保留。

## 账号管理

管理员可在顶部「账号」进入账号管理。创建时填写显示名称、账号和 12 至 128 字符的初始密码，并选择「标注员」或「管理员」。登录账号可使用汉字、英文字母、数字、点、下划线和连字符。含汉字时为 1 至 32 个字符，其他账号为 3 至 32 个字符。管理员可查看全部作业、导入送审包并创建其他账号。停用、启用和重置密码操作适用于标注员。

## 送审包

ZIP 根目录含 `pairs/`，图像从 `pairs/0001.jpg` 连续编号。支持 JPG、PNG。每张图上半幅为原片，下半幅为待审画面，两半等高，同版尺寸一致。单包上限为 2,400 帧、256 MiB 展开大小。返修版帧数与基版相同。

`manifest.json` 可提供原片文件的 SHA-256 以及逐帧时间线。推荐使用有理数 `time_base` 和整数 `pts`、`end_pts`，以保留变帧率和末帧时长。下例是一个三帧时间线，使用输出原片文件的实际摘要填充 `source_sha256`。

```json
{"source_sha256":"0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef","time_base":"1/30000","pts":[0,1001,2302],"end_pts":3303}
```

也支持整数毫秒 `time_ms` 和 `end_ms`。时间线从零开始并严格递增。缺少原片摘要或时序时仍可送审，返修版由人工复核相应帧。旧版本记录保持其原有审核结果。

`demo/` 内含两组模拟送审包的 V1 和 V2。执行 `python3 make_demo.py demo` 可重新生成。执行 `python3 make_demo.py /tmp/review-hd 1920` 可生成 1920×2160 对比图。

## 客户端上传 API

使用 `POST https://10.10.10.247/api/v1/review-packages`，请求类型为 `multipart/form-data`，发送 `Authorization: Bearer <上传 Token>`。接口复用上文的 ZIP 格式和大小限制。服务端存储 Token 的 SHA-256 摘要到 `/etc/movie-review.env` 的 `MOVIE_REVIEW_UPLOAD_TOKEN_SHA256`，并用 `MOVIE_REVIEW_UPLOAD_ACTOR` 指定审计关联的管理员账号（默认 `admin`）。上传 Token 只用于此接口。审核页仍由标注员登录操作。

| 场景 | 表单字段 |
| --- | --- |
| 新建送审作业 | `title`（1–120 字），`package`（ZIP 文件） |
| 上传返修版 | `job_id`（作业 ID），`base_version`（已退回版号），`package`（ZIP 文件） |

```bash
curl --config upload.curl \
  --form-string 'title=街角转弯' \
  --form 'package=@review.zip' \
  https://10.10.10.247/api/v1/review-packages
```

在本机联调时，将 `upload.curl` 替换为私有凭据文件的路径。其他客户端可直接设置认证请求头，并信任配套的 `site.crt`。当前证书是内网自签名证书。

```json
{"job_id":123,"version":1,"reused":false,"review_path":"/jobs/123?v=1"}
```

首次受理返回 `201`。在相同作业名或相同返修作业与基版下重传字节一致的 ZIP，返回 `200` 和已有版本。返修状态或版号冲突返回 `409`。应用错误包含 `error.code` 和 `error.message`，例如 `401 invalid_token`、`403 https_required`、`422 invalid_package`。超过网关请求大小上限时，网关可直接返回 `413`。

## 执行管理与设备接入

1. 管理员在 HTTPS 上打开「执行管理 → 设备」，登记设备并复制服务地址、节点标识和建模 Token。客户端保存连接信息后启动节点。使用内网自签名证书时，客户端需要信任服务器证书。
2. 在「执行管理 → 工单」上传原片。系统以文件名创建首版工单。同一份视频文件重复上传时，页面会显示已有作业编号。
3. 在线且有空闲槽位的设备主动领取首版。服务器只把一条待领工单交给一台设备。续租超时、制作失败或密钥暂停后，工单保留原设备并显示「待处理」。管理员可在「工单操作 → 退回待领」填写原因。退回立即结束原领取资格，领取记录保留设备、时间及退回信息。
4. 首版回传后进入审核队列。审核退回可生成返修工单，通过审核可生成出片工单。出片后的交付包和视频可在工单中下载。

执行端使用本机制作配置。上传新作业时可以选择「集中存储」或「同机审片」。首版处于待领取或无归属的已暂停状态，且审核版本尚未入库时，管理员可在「工单 → 查看详情 → 概览」修改审片存储。已退回待领的工单也可修改。模式从下一次领取生效，历史领取和退回记录保留。同机审片绑定声明支持该协议的执行实例，返修、出片和补审返修继续由原实例领取。审片 ZIP 只上传对比 JPG 和索引，工程和无损白模帧留在执行端。返修和出片引用审核基版的原始版本清单及其 SHA-256。

管理员可在上传页和作业详情设置 1080p 或 4K。新作业默认 1080p。出片工单生成时冻结 `export_quality`。4K 需要审核基版原生宽度为 3840，1080p 出片保持画面比例。

密钥可暂停、恢复、撤销或从列表移除。密钥轮换时可先签发新密钥，确认连通后再暂停旧密钥。机器 Token 用于制作工单协议，独立 ZIP 送审使用它自己的上传 Token。续租期限为 90 秒。低于客户端设定的磁盘预留值时暂停领取新工单，当前工单可以续租。

网页原片上传受现有反代请求上限约束。工单产物走 8 MiB 分块上传，每个对象最大 16 GiB。执行端审片包最多 2400 帧，每张对比图最大 14 MiB，ZIP 展开后最大 16 GiB。网页及独立 API 上传的送审包上限为 256 MiB。Ubuntu 运行调度、索引与审核，实际制作及媒体技术核验由执行端负责。

## Ubuntu 内网运行

- `nginx.service` 和 `movie-review.service` 随系统启动。联调主机的 Nginx 在 IPv4 和 IPv6 上监听 80（纯 HTTP）和 443（HTTPS），接受可路由的来源地址。审核操作需要登录。应用以 `movie-review` 账号运行，反向代理使用 `127.0.0.1:18080` 访问它。
- 应用位于 `/opt/movie-review/app`，Python 依赖位于 `/opt/movie-review/lib`。SQLite 和私有文件目录位于 `/var/lib/movie-review`。
- 可用 `systemctl status movie-review.service` 查看状态，`sudo journalctl -u movie-review.service -n 60` 查看日志。
- `deploy/install-linux.sh` 接收离线部署目录和私有账号 JSON。部署目录包含 `app/`、`lib/` 和 `movie-review.service`。Ubuntu 侧使用系统 Python 3.12，`lib/` 从适配 Ubuntu x86_64 的 Wheel 安装。
- `deploy/upgrade-linux.sh` 接收待部署的应用目录，升级前备份，初始化增量表并检查健康状态。升级失败时恢复上一版应用。数据库迁移采用增量建表和增量字段。
- `sudo bash /opt/movie-review/app/deploy/backup-linux.sh` 会生成 SQLite 一致性快照、图片和应用密钥。备份及校验文件保存在 `/var/backups/movie-review`，访问权限仅限 root。脚本会在隔离目录解包，检查数据库及各帧资源。
- 生产恢复时先暂停服务，校验归档摘要，在临时目录解包并执行 `verify-backup.py`。将已验证的数据库、`assets` 和存在时的 `execution-incoming` 恢复到 `/var/lib/movie-review`，权限归 `movie-review`，密钥恢复到 `/etc/movie-review.env` 并设为 root 可读。恢复后可删除 `sessions` 表中的会话，要求所有账号重新登录。启动后检查健康接口和历史图像。
- `deploy/movie-review.nginx` 安装到 `/etc/nginx/sites-available/movie-review` 并链接到 `sites-enabled`。`deploy/movie-review-proxy.conf` 安装到 `/etc/nginx/snippets/`，由 HTTP 和 HTTPS 两段站点配置共用。`deploy/movie-review.public-listeners.conf` 安装为 `/etc/systemd/system/movie-review.service.d/public-listeners.conf`。它将后端移至本机回环地址，允许应用信任 Nginx 设置的一个客户端地址和协议。启用站点前检查 `nginx -t`，切换后检查两个入口的 `/health`。初装脚本默认部署内网直连服务。
- HTTPS 当前使用 `/etc/movie-review/tls/site.crt` 中匹配 `10.10.10.247` 的自签名证书。客户端需要建立证书信任。更换证书和私钥后用 `nginx -t` 校验，再重载 Nginx。公网发布时配置域名和受信任证书，并在上游入口映射 443。

## 回归

用 `python3 -m unittest discover -s tests -v` 运行审核状态、权限、送审包重试、时序继承、账号撤销和返修包回归。

管理员可在「账号」删除标注员或其他管理员。删除后立即注销会话并移出账号列表，保留作业归属和历史记录，原账号名继续保留。该账号仍有进行中的审核时，作业显示为等待。当前登录账号和已配置的客户端送审上传服务账号受保护。

通过 HTTPS 打开「执行管理 → 设备」，可绑定最近注册的实例。后台会拒绝该节点使用其他实例标识注册、上报心跳或领取工单。更换客户端前可解除绑定。实例标识由客户端上报，可被复制，硬件身份验证需要执行端签名。
